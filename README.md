# Парсер карточек Ozon

Тестовый проект для согласованного сценария: пользователь вручную входит в Ozon Analytics в видимом браузере, скрипт сохраняет cookies, а второй скрипт запрашивает карточки товаров и экспортирует данные в CSV. Основной режим использует Selenium; для сайтов, отклоняющих WebDriver-сессию, предусмотрен явно ручной диагностический fallback.

Gmail API не используется. Скрипт не обходит CAPTCHA и антибот-проверки. Динамические query-параметры `data.ozon.ru` не хардкодятся.

## Что входит в проект

- `get_cookies.py` — открывает Edge, Chrome или Яндекс.Браузер, ждёт ручного входа и сохраняет сессию в `data/cookies.json`;
- `parse_ozon.py` — получает карточки через `requests.Session`, читает встроенный JSON и записывает `output/products.csv`;
- `output/errors.csv` — отдельный отчёт по SKU, которые не удалось обработать;
- `debug/product_<sku>.html` — диагностический HTML при ошибке извлечения;
- `tests/` — полностью офлайн-тесты на синтетических JSON/HTML-фикстурах.

Каталоги `data/`, `debug/` и `output/` исключены из Git. Cookie-файл и живой HTML могут содержать персональные данные — их нельзя отправлять работодателю или коммитить.

## Установка в PowerShell

Требуется Python 3.9+ и установленный Microsoft Edge. Из корня проекта:

```powershell
py -3.9 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

Если политика PowerShell запрещает активацию, можно не менять её и использовать `\.venv\Scripts\python.exe` во всех командах ниже.

Selenium Manager входит в Selenium 4 и сам подбирает драйвер. Для Edge и Chrome вручную скачивать драйвер не требуется. Локальный ChromeDriver поддерживается только как необязательный fallback для Яндекс.Браузера, когда системный VPN блокирует загрузку Selenium Manager.

Скрипт сам ищет Edge в стандартных каталогах Windows и явно передаёт найденный путь Selenium Manager. Для нестандартной установки путь можно задать переменной `OZON_EDGE_BINARY`, как показано в `.env.example`.

## 1. Ручной вход и сохранение cookies

```powershell
.\.venv\Scripts\python.exe .\get_cookies.py
```

В открывшемся Edge:

1. Пройдите антибот-проверку, если она появилась.
2. Нажмите «Перейти к аналитике».
3. Войдите в Ozon ID вручную.
4. Подтвердите вход через мобильное приложение.
5. Дождитесь полной загрузки страницы аналитики.
6. Вернитесь в PowerShell и нажмите Enter.

Скрипт проверит домен, наличие Ozon cookies и User-Agent, сохранит только нужные поля и закроет браузер. Значения cookies в лог не выводятся.

Для Яндекс.Браузера:

```powershell
.\.venv\Scripts\python.exe .\get_cookies.py --browser yandex
```

Скрипт автоматически определяет внутреннюю major-версию Chromium Яндекс.Браузера и передаёт её Selenium Manager для выбора совместимого ChromeDriver. Для текущей локальной установки Яндекс.Браузера `26.8.0.1788` обнаруживается Chromium `150`.

Если системный VPN блокирует загрузку Selenium Manager, скрипт может использовать совместимый драйвер из `data/webdriver/chromedriver.exe`. Этот каталог игнорируется Git и служит только локальным fallback; бинарник нельзя включать в отправляемый проект. Путь можно переопределить через `OZON_CHROMEDRIVER_PATH`.

Если Ozon открывается в обычном браузере, но отклоняет именно WebDriver-сессию, доступен явно ручной fallback:

```powershell
.\.venv\Scripts\python.exe .\get_cookies.py --browser yandex --manual-capture
```

В этом режиме Selenium не подключается к странице. Скрипт запускает обычный видимый браузер с отдельным временным профилем и локальным DevTools-портом только на `127.0.0.1`. После ручного входа стандартная команда CDP `Storage.getCookies` экспортирует Ozon cookies с исходными доменами и путями. Затем браузер закрывается, а временный профиль удаляется. Основной Selenium-сценарий остаётся режимом по умолчанию; ручной fallback документирует фактически подтверждённое ограничение live-среды.

Для диагностики структуры конкретной карточки можно добавить `--capture-product-html <SKU>`. После входа скрипт попросит вручную открыть карточку в том же окне и сохранит её текущий DOM в игнорируемый `debug/product_<sku>.html`.

Для Chrome:

```powershell
$env:OZON_BROWSER = "chrome"
.\.venv\Scripts\python.exe .\get_cookies.py
```

## 2. Получение товаров

Без аргументов используются два SKU из задания:

```powershell
.\.venv\Scripts\python.exe .\parse_ozon.py
```

Явный список SKU:

```powershell
.\.venv\Scripts\python.exe .\parse_ozon.py 2359066702 2829800382
```

Или UTF-8 файл с одним SKU на строку:

```powershell
.\.venv\Scripts\python.exe .\parse_ozon.py --sku-file .\skus.txt
```

Один ошибочный SKU не останавливает пакет. Запросы имеют timeout, ограниченные повторы с backoff для 429/5xx и паузу между товарами. Распознаются 403, 404, 429, 5xx, антибот/CAPTCHA, переход на авторизацию, пустая страница и отсутствие ожидаемого JSON.

## Результаты

`output/products.csv` содержит только обязательные колонки в стабильном порядке:

```text
sku,title,price,rating,reviews_total,cover_image,photos_seller,videos_seller,color,material,art_set,has_rich_content
```

Не найденные необязательные значения остаются пустыми. Цена, рейтинг и отзывы нормализуются в числа. Старую зачёркнутую цену парсер намеренно не использует.

Ошибки записываются в `output/errors.csv` с колонками `sku,error_type,message`.

## Диагностика реальной страницы

Структура встроенного JSON Ozon может меняться. Если ожидаемые данные не найдены, скрипт сохраняет ответ в `debug/product_<sku>.html` и указывает этот путь в логе и `errors.csv`. Этот файл нужен для локальной донастройки парсера, но его нельзя коммитить или пересылать без проверки на персональные данные.

Для локальной диагностики успешного ответа можно явно добавить `--save-html`. Без этого флага успешные HTML не сохраняются.

Если прямой HTTP-запрос отклоняется защитой Ozon, ранее сохранённые через `--capture-product-html` страницы можно проверить тем же извлекателем и выгрузить в основной CSV без новых сетевых запросов:

```powershell
.\.venv\Scripts\python.exe .\parse_ozon.py --html-dir .\debug
```

Это диагностический fallback, а не скрытая замена основного режима: без `--html-dir` скрипт всегда использует cookies, `requests.Session`, timeout, retries и backoff.

Наличие офлайн-тестов не доказывает, что текущая live-структура Ozon совпадает с синтетической. Реальную работу необходимо подтвердить после ручного входа.

## Настройки

Примеры переменных окружения находятся в `.env.example`. Основные параметры также доступны как аргументы:

```powershell
.\.venv\Scripts\python.exe .\parse_ozon.py --timeout 30 --retries 3 --backoff 1 --delay 1.5
```

## Тесты

```powershell
.\.venv\Scripts\python.exe -m pytest -q
```

Тесты не обращаются к Ozon и не требуют cookies.
